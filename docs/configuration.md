# Configuration

Every key is optional. Without a config file, `sb` uses the defaults below.

## Where settings come from

| Setting | Order of precedence |
|---|---|
| Vault folder | `--vault`, then `$SECONDBRAIN_VAULT`, then `vault` in the config file |
| Config file | `--config`, then `$SECONDBRAIN_CONFIG`, then `$XDG_CONFIG_HOME/secondbrain/config.toml` (default `~/.config/secondbrain/config.toml`) |
| Processing state | `$SECONDBRAIN_STATE_DIR`, then `state_dir` in the config file, then `$XDG_STATE_HOME/secondbrain` (default `~/.local/state/secondbrain`) |

The config file is TOML. An unknown section or key is an error, so a typo does not go unnoticed. `sb doctor` prints the file it read, the vault, the layout and the endpoints.

The processing state (frozen inputs, task files, answers, run records, the transaction journal and the lock) must live outside the vault. Each vault gets its own folder inside it, named by a hash of the vault path.

## Full example

```toml
vault = "~/Obsidian/MyVault"
# state_dir = "~/.local/state/secondbrain"

[layout]            # folder names inside the vault; defaults shown
knowledge = "10_Knowledge"
mocs = "20_MOCs"
taxonomy = "20_MOCs/_pillars"
sources = "40_Sources"
inbox = "00_Inbox"
reviews = "50_Reviews"
data = "_data"
entry_docs = []     # top-level notes whose generated blocks `sb docs` refreshes, e.g. ["Guide.md"]

[executor]
default = "api"     # api | host

[executor.producer]
kind = "openai"     # openai (any OpenAI-compatible endpoint) | anthropic
base_url = "https://api.example.com/v1"
model = "producer-model-name"
api_key_env = "SB_PRODUCER_API_KEY"
max_output_tokens = 32000
timeout_s = 600

[executor.reviewer]  # use a model of a different family than the producer
kind = "anthropic"
base_url = "https://api.anthropic.com"
model = "reviewer-model-name"
api_key_env = "SB_REVIEWER_API_KEY"

[review]
require_different_family = true
allow_same_family_in_host_mode = true
withhold_producer_reasons = true
max_repair_rounds = 1

[model_families]    # substring -> family, merged over the built-in table
# my-local-model = "local"

[ingest]
chunk_chars = 12000
after_ingest = "move"        # move | keep
new_topics_per_source = 2
converter = "none"           # none | markitdown
id_prefix = "kc_"

[cards]
language = "en"              # en | zh (card headings; text of maps, HOME and review pages)
diagrams = true              # one extra model call per 10 new cards; Mermaid is generated by code

[taxonomy]
extra_reviewers = 0

[git]
commit = false
```

## Keys

### Top level

| Key | Default | Meaning |
|---|---|---|
| `vault` | none | The vault folder. `~` is expanded. |
| `state_dir` | see above | Where processing state is kept. Must not be inside the vault. |

### `[layout]`

Folder names are relative to the vault. Folders must not overlap.

| Key | Default | Holds |
|---|---|---|
| `knowledge` | `10_Knowledge` | cards, one folder per domain: `<knowledge>/<domain>/<title>.md` |
| `mocs` | `20_MOCs` | generated map pages, one root page per MOC and one folder of pillar pages |
| `taxonomy` | `20_MOCs/_pillars` | one YAML file per MOC with its pillars and topics |
| `sources` | `40_Sources` | copies of ingested sources: `<sources>/<first 16 hex of sha256>/<file name>` |
| `inbox` | `00_Inbox` | new material |
| `reviews` | `50_Reviews` | the generated daily review page (`sb today`) |
| `data` | `_data` | registries, the catalog, review logs |
| `home` | `HOME.md` | the generated entry page |
| `entry_docs` | none | hand-written top-level notes whose generated blocks `sb docs` refreshes, for example `["Guide.md"]` |
| `extra_dirs` | `30_Exercises`, `90_Meta` | more top-level folders counted in the folder table on the entry page |

### `[executor]`, `[executor.producer]`, `[executor.reviewer]`

| Key | Default | Meaning |
|---|---|---|
| `default` | `api` | Executor when a command has no `--executor`. `host` hands each step to a sub-agent; `api` calls the endpoints. |
| `kind` | `openai` | `openai` for any OpenAI-compatible `/chat/completions` endpoint; `anthropic` for `/v1/messages`. |
| `base_url` | none | Endpoint base URL. |
| `model` | none | Model name sent to the endpoint. |
| `api_key_env` | none | Environment variable that holds the key. |
| `api_key_cmd` | none | Command that prints the key (split like a shell command, not run through a shell, 30 s timeout). |
| `max_output_tokens` | 32000 | Output limit per call. |
| `timeout_s` | 600 | Timeout per call. |
| `max_retries` | 3 | Retries on rate limits and server errors (with back-off, honouring `retry-after`). |
| `structured_output` | `auto` | `auto` tries JSON Schema output, then JSON mode, then plain text; or force `json_schema` or `json_object`. |

A key written into the file (`api_key = ...`) is refused. Keys are read per request and never logged or stored.

### `[review]`

| Key | Default | Meaning |
|---|---|---|
| `require_different_family` | true | Producer and reviewer must be different model families when the model name comes from the provider's response (API executor). |
| `allow_same_family_in_host_mode` | true | In host mode the model name is self-reported; a same-family pair is allowed and the job records `same_family: true`. |
| `withhold_producer_reasons` | true | The reviewer does not see the producer's reasons. |
| `max_repair_rounds` | 1 | Repair rounds per chunk for rejected or invalid cards. `sb ingest --max-rounds N` overrides it for one run. |

### `[model_families]`

Maps a substring of a model name to a family, for the independent-review check. The built-in table knows `claude`, `gpt`, `o1`, `o3`, `o4`, `gemini`, `gemma`, `glm`, `deepseek`, `qwen`, `kimi`, `moonshot`, `grok`, `llama`, `mistral` and `mixtral`. Your entries are merged over it.

### `[ingest]`

| Key | Default | Meaning |
|---|---|---|
| `chunk_chars` | 12000 | Target chunk size in characters (1,000 to 400,000). Chunks split at headings and blank lines, then at sentence ends. |
| `after_ingest` | `move` | `move` removes the inbox file in the same transaction (its bytes are kept in `sources`); `keep` leaves it in the inbox. |
| `new_topics_per_source` | 2 | New topics a producer may propose for one source. |
| `converter` | `none` | `markitdown` converts non-text files (needs the `markitdown` package). |
| `id_prefix` | `kc_` | Card ids are this prefix plus the card's slug. |
| `max_source_bytes` | 8 MiB | Larger sources are refused, not truncated. |
| `neighbors_per_card` | 3 | Existing cards shown to the reviewer per new card. |
| `candidate_domains` | 3 | Domains whose taxonomy a producer sees for one chunk. |

### `[cards]`

| Key | Default | Meaning |
|---|---|---|
| `language` | the vault's language | `en` or `zh`. Sets the section headings of new cards (`en`: Essence, Propositions, Diagram, Intuition and contrasts, Related, Review cards) and the fixed text of the generated pages: maps, `HOME.md` and the daily review page. Card text follows the language of the source. Without this key, `sb` uses the vault's language (recorded in the catalog, else found from its maps, else `en`). If this key names another language than the vault's, writes are refused until `sb language --set` switches the vault. |
| `diagrams` | true | Run the diagram step after review ([diagrams.md](diagrams.md)). |

### `[taxonomy]` and `[git]`

| Key | Default | Meaning |
|---|---|---|
| `extra_reviewers` | 0 | Reserved. Values above 0 are not supported yet. |
| `commit` | false | After a write, commit exactly the written paths to the vault's git repository. A failed commit is recorded and does not roll back the write. |

## Environment variables

| Variable | Meaning |
|---|---|
| `SECONDBRAIN_VAULT` | vault folder |
| `SECONDBRAIN_CONFIG` | config file |
| `SECONDBRAIN_STATE_DIR` | processing-state folder |
| `SECONDBRAIN_LOCK_WAIT` | seconds to wait for another writer's lock (default 30) |
| `SECONDBRAIN_NO_CACHE=1` | read every card from disk, without the parse cache |

## Install extras

| Extra | Adds | Needed for |
|---|---|---|
| `api` | `httpx` | the API executor |
| `mcp` | `mcp` | `sb serve` |
| `review` | `fsrs` (pinned) | `sb review`, `sb today` and the review page of `sb daily` (without it, `sb daily` writes `HOME.md` only); the review totals in `sb status` |
| `test` | all of the above and `pytest` | running the tests |
