# Changelog

## 0.1.0 (unreleased)

First public version.

- Ingest chain: inbox status, frozen sources and chunks, producer and independent reviewer, deterministic checks, repair rounds (two by default), review gate, one recoverable vault transaction, optional git commit.
- Ingest gate: relation types opened per domain, one relation per pair of cards, a card that only repeats existing cards not written, and disagreements with existing cards recorded in `_data/secondbrain/conflicts.jsonl` and listed by `sb status`.
- Executors: host hand-off for sub-agents of a coding-agent harness; API clients for OpenAI-compatible and Anthropic endpoints, with a model-family check. Transport and gateway errors (rate limits, server errors, 401/403 behind a gateway, timeouts, empty response bodies) are retried inside the executor with back-off (`max_retries`, 0 to 10); they are not answers and use none of `max_invalid_retries`.
- Entry points: the `sb` CLI, an Agent Skill (`skills/secondbrain`), and an MCP server with separate read-only and writer launches.
- Taxonomy and maps of content: domain, pillar and topic for every card; MOC pages regenerated in prerequisite order, with `BC-list-note-field: down` front matter for the Breadcrumbs plugin (the first `sb refresh --apply` adds it to existing domain and pillar pages, once); topics proposed by the producer and accepted by the reviewer.
- Generated pages (maps, `HOME.md`, the daily review page) in English or Chinese, like the card headings. The vault records its language in the catalog; `sb language` shows it and `sb language --set` switches it.
- `sb ingest --retry <job>` for the pending cards of a partial job, as a child job that is rolled back before its parent; its chunk reviewer judges the retried cards against the cards the source already wrote, on the same repeat scale; `sb recover <job> --rollback` and `--resume`; `sb job prune` for old rollback journals (preview unless `--apply`).
- Candidate cards: one retrieval entry for every role (`via`: `named`, `written`, `words`, `hop`, `shelf`), four card views (`title`, `brief`, `full`, `body`) and one character budget, `[ingest] candidates_chars` (40,000), packed in a fixed order; 15 search hits per query for every role over the whole vault, no second route, long item blocks searched line by line.
- Review packet: every existing card the producer named, whole; search hits at `brief` (`[ingest] review_words_view`; `full` with a Flash reviewer); topic shelves by title for the producer and the reviewer.
- Repeat scale: one scale, `same` / `extends` / `distinct`, for every judge; one final judge per value and an append-only decision record per job; the review rules and `[ingest]` settings frozen with each job.
- Merge into existing cards: a card that extends an existing card goes into it as a patch (new propositions, a replaced proposition, new review cards, a review card swapped for a fuller or clearer one, a source, relations; nothing else changes; the review schedule is kept by card, so a swapped question keeps the card's progress); past 12 propositions or 8 review cards it is rewritten as a narrower card in a split slot, which gets only that card's additions and whose reviewer maps each proposition to the existing card (`matches`, `split_restated`); a card whose propositions the existing card all says gets no slot, and the review cards it carries go in as a patch of their own (held when they would pass 8); `[ingest] merge_into_existing` turns this off, and the decision record then says the card is written (`outcome.program`).
- Merge check (the source check, `xc01`): judges the source's `distinct` cards, its new topics and one patch per existing card; every proposition and every review card accounted for (carried, swapped in, or named in `already`), a point said twice sent back (`differs` for a close wording), judged by the question and never by size, disputes sent back to the chunk reviewer (the next round runs on the cards that are left, so the round before is replaced, never left half applied), a `replace` that keeps every fact of the proposition it replaces (and is used, not an added proposition, for a carried proposition about the group of names or terms a proposition of the card sums up), a `flashcard_replace` that swaps one review card of the card a patch or carry goes into for a fuller or clearer one and keeps every fact of its answer (each review card once, the new pair checked like a carried review card, every swap listed with its words before and after, a swap whose patch goes to a split slot not made and listed in `replacements_not_made`), the last answer kept patch by patch and carry by carry (`patches_held`; a card whose carry is held is written as a card of its own), a run that ended in a transport error not counted as an answer; candidate rows by id; `source_check_refusals`, `patch_set`, `merge_set`, `merged_into_existing` and `split` in the job result, the fate of every card that goes into another recorded in the decision record (`outcome.program`, `pending` included) and read back from there.
- Context note: each chunk of a longer source gets the headings it starts under, the end of the chunk before and the source's outline, only for understanding (`[ingest] context_note`, `context_note_chars`).
- Review rules: two budgets, `[review] max_repair_rounds` (2) and `max_invalid_retries` (2); every role that asks a model (one table of roles) counts its answers that failed the checks per slot in the job state, so one `sb job advance` asks at most `max_invalid_retries` + 1 times and a job run again does not start over (a host sub-agent's answers that `sb job submit` refuses count the same, a file that is not JSON or a value that is not an object and a run given up with `sb job abandon` included, all at one gate, for every job kind that asks a model, maintenance jobs too, whose answers are checked when submitted; every answer, from a host's file, the MCP tool or an API executor, is taken through one entry point that reads it, checks its size, takes out the fields only the program writes, checks, stores and records it; only a refusal a check raises on purpose is the answer's own (the tests read every raise a check can reach from the source), and any other error there is counted too and listed for the owner with its stage (`kind: program_error`); a maintenance job's review is checked when taken for covering its proposal; what every job kind does afterwards with the answers it took runs behind one guard, which sets the answer to blame aside and counts it (taking back what it put in the decision record), or parks the job for the owner when no one answer is to blame or the same error comes back after a set-aside, so no error stops every later advance (the packets a host asks for and a resumed write included; a parking ends once an advance gets past it); a stop on purpose still stops the job and is listed (`kind: job_stopped`); a run is closed once its slot is given up); then a chunk's cards, a split card (its producer or its reviewer) or a disputed card (its judgement again) wait for the owner with the reason, and the merge check, a model note or a diagram is done without; mechanical fixes (`amend`); a focused review in repair rounds; every sentence of a card's essence, intuition and confusions checked against the chunk or a card it names by `[[Title]]` (the producer told the same, also for the confusion a `contrasts_with` relation calls for), and a fact with neither source a `fact` note; notes of five kinds, and an accept with a `fact`, `unreadable`, `quote` or `not_a_unit` note becomes a revise (each proposition must be right on its own) (`notes_turned`, `review_notes`, shown by `sb job show`); a card answers one question: its reviewer writes that question (`question`, kept in the review and shown to the merge check, not written to the card) before its decision and checks each proposition and review card against it, items of another question are a `not_a_unit` note, the answer to a sub-question may stay, a card's sixth kind of note, `repeats` (two propositions make one point, or two review cards ask one question; two review cards on one proposition from different sides do not), sends it back as well, an example gives its premises on the card or is `unreadable` (a premise another chunk gives is written with that chunk's card named by `[[Title]]`), the producers read `repeats` and the premises from the same definitions, and a card that extends an existing card answers that card's question (the merge check writes it in each patch's `question` and disputes a card of another question); `tools/review_replay.py` gives a reviewer's task of an earlier job this version's instructions and schema (assembled by the job's own functions), and reads an answer as the program does: an answer the program would refuse prints `REFUSED`.
- Answer checks: every model answer is type-checked against its schema; a card's title, which names its file, is at most 120 characters and 200 bytes in UTF-8 (66 Chinese or Japanese characters), a longer one sent back to be shortened; a wrong shape is refused by name and asked for again, never a crash; ingest answers are parsed as strict JSON, and an answer is read the same way in API and host mode: as it is, else without one Markdown code fence, else its JSON object alone when words stand around it (`fence`, `around` in `program_repairs`). A split card's text and quotes are repaired in the same place as a chunk's cards, and a card a slot's last answer held back keeps its text in the pending item. A chunk producer's answer is first repaired by a table of rules that write no knowledge text (a title character written full width, a card id written as `[[Title]]`, a quote that differs from the chunk only by bold marks or spaces, extra or reversed relations and relations to cards that do not exist), each repair recorded in the job result (`program_repairs`) and shown to the reviewer, a card that names another by `[[Title]]` and by id is repaired (both sides of the guard are compared in one written form; a card id is rewritten once, only where it stands alone between characters that are not ASCII letters, digits or underscores, so an id set against Chinese text is found, and a link whose target is an id becomes a link to the title), and a repair that would change knowledge text is refused and counted as the program's error; then a card that still fails is refused alone, for one refusal however many cards, asked for again with its error lines (`fix`) and put back with the cards that passed, and the slot's last answer keeps the cards that pass while the others wait for the owner; a problem of the whole chunk refuses the whole answer.
- Text comparison: one test of "the same text", which sets aside only case, width, spaces and a closed table of marks; a finding only sends an answer back. What the program leaves out by itself is decided in one place: a proposition in the very same words (spaces aside), or a review card whose question and answer both are. A review card that asks the same question with another answer goes back naming both answers (`differs` may keep both). Before a card that takes a patch or a carry is written, the program checks that every item of it is in the card, and stops otherwise.
- Status: `sb status --owner-items` lists everything that waits for the owner, a maintenance job that stopped (its answers kept failing the checks, or its repair rounds ran out) included, with the step and the reason (`kind: maintenance_job`); `sb status` reports topics past 25 cards, and `sb curate` gets split proposals for them (extra `curate`).
- `sb export`: writes one map's cards up as an article: outline from the taxonomy, unit after unit by default (`[export] mode`), the writer and reviewer set in `[export.writer]` and `[export.reviewer]`, independent review and smoothing, program checks of citations, numbers and formulas (a MathJax check before any model call, its script installed with the package so an install from git or a wheel has it, a literal `\n` caught), paragraphs that never passed marked in the text and listed; answers that keep failing the checks counted in the job against `max_invalid_retries` (in host mode too), then the unit marked as not reviewed (or, never written, marked where it would stand with why and the cards it was to cover, and listed); a unit whose review says the same words again in the next round counts that round (before, it was repaired without end); Markdown, a report and optional HTML (extra `export`).
- Older jobs: a retry of a partial job of the earlier version is a job of this version and runs to the end; a running job of the earlier version says how to reset it; a job keeps the settings it was frozen with.
- Card diagrams: the model returns a diagram IR that cites the card; code validates it and generates Mermaid, or the card gets no diagram. Batch tools for diagrams already in a vault: audit, prune, re-judge, old-diagram audit, layout gate with the Mermaid build Obsidian ships, write-back.
- Review registry: append-only review log per device, FSRS replay in Python and TypeScript with shared test vectors, `sb review status|queue|log|import-sr`; the daily review page (`sb today`) shows the same queue.
- Obsidian plugin SecondBrain Review: English and Chinese interface that follows the vault's language; today view and dashboard, flip review, Q&A review with LLM grading through AI Providers, card explanations with map context, reminders, one-time import of Spaced Repetition schedules.
- Card formulas: code puts them between `$` and gives a bare macro name its backslash; a relation symbol's name used as a function name (`sim(q, d)`) is written `\operatorname{sim}`, not the relation `\sim` (a binary operator before a group, `times(`, stays the operator), and `sigmoid` and `relu` are operator names like `softmax`.
- Configuration in TOML, configurable folder layout, keys only from environment variables or commands.
- Vault snapshot cache outside the vault: it compares each card file's bytes with the cached copy and parses only what changed, so a card rewritten with the same size within one timestamp tick is read again; writes always check real file hashes.
- `sb init --catalog <file>` puts a hand-written catalog into a vault, adds the empty card registry and folders, and lists the taxonomy files still to write; until one domain has a topic, `sb ingest` stops before any model call.
- Two example vaults built with the Agent Skill and the tool's own ingest chain: English (42 cards) and Chinese (52 cards).
- README and guides in English and Chinese (`*.zh-CN.md`).
