# Changelog

## 0.1.0 (unreleased)

First public version.

- Ingest chain: inbox status, frozen sources and chunks, producer and independent reviewer, deterministic checks, repair rounds (two by default), review gate, one recoverable vault transaction, optional git commit.
- Ingest gate: relation types opened per domain, one relation per pair of cards, a card that only repeats existing cards not written, and disagreements with existing cards recorded in `_data/secondbrain/conflicts.jsonl` and listed by `sb status`.
- Executors: host hand-off for sub-agents of a coding-agent harness; API clients for OpenAI-compatible and Anthropic endpoints, with a model-family check. Transport and gateway errors (rate limits, server errors, 401/403 behind a gateway, timeouts, empty response bodies) are retried inside the executor with back-off (`max_retries`, 0 to 10); they are not answers and use none of `max_invalid_retries`.
- Entry points: the `sb` CLI, an Agent Skill (`skills/secondbrain`), and an MCP server with separate read-only and writer launches.
- Taxonomy and maps of content: domain, pillar and topic for every card; MOC pages regenerated in prerequisite order, with `BC-list-note-field: down` front matter for the Breadcrumbs plugin (the first `sb refresh --apply` adds it to existing domain and pillar pages, once); topics proposed by the producer and accepted by the reviewer.
- Generated pages (maps, `HOME.md`, the daily review page) in English or Chinese, like the card headings. The vault records its language in the catalog; `sb language` shows it and `sb language --set` switches it.
- `sb ingest --retry <job>` for the pending cards of a partial job, as a child job that is rolled back before its parent; its chunk reviewer judges the retried cards against the cards the source already wrote, on the same repeat scale; `sb recover <job> --rollback` and `--resume`; `sb job prune` for old rollback journals (preview unless `--apply`).
- Candidate cards: one retrieval entry for every role (`via`: `named`, `written`, `words`, `hop`, `shelf`), four card views (`title`, `brief`, `full`, `body`) and one character budget, `[ingest] candidates_chars` (40,000), packed in a fixed order; 15 search hits per query for every role over the whole vault, no second route, long item blocks searched line by line.
- Review packet: every existing card the producer named, whole; search hits at `brief` (`[ingest] review_words_view`; `full` with a Flash reviewer); topic shelves by title for the producer and the reviewer.
- Repeat scale: one scale, `same` / `extends` / `distinct`, for every judge; one final judge per value and an append-only decision record per job; the review rules and `[ingest]` settings frozen with each job.
- Merge into existing cards: a card that extends an existing card goes into it as a patch (new propositions, a replaced proposition, new review cards, a review card swapped for a fuller or clearer one, a source, relations; nothing else changes; the review schedule is kept by card, so a swapped question keeps the card's progress); past 12 propositions or 8 review cards it is rewritten as a narrower card in a split slot, which gets only that card's additions and whose reviewer maps each proposition to the existing card (`matches`, `split_restated`); a card whose propositions the existing card all says gets no slot, and the review cards it carries go in as a patch of their own (held when they would pass 8); `[ingest] merge_into_existing` turns this off, and the decision record then says the card is written (`outcome.program`).
- Merge check (the source check, `xc01`): judges the source's `distinct` cards, its new topics and one patch per existing card; every proposition accounted for (`already`), a point said twice sent back (`differs` for a close wording), judged by the question and never by size, disputes sent back to the chunk reviewer (the next round runs on the cards that are left, so the round before is replaced, never left half applied), a `replace` that keeps every fact of the proposition it replaces, a `flashcard_replace` that swaps one review card of the card a patch or carry goes into for a fuller or clearer one and keeps every fact of its answer (each review card once, the new pair checked like a carried review card, every swap listed with its words before and after, a swap whose patch goes to a split slot not made and listed in `replacements_not_made`), the last answer kept patch by patch and carry by carry (`patches_held`; a card whose carry is held is written as a card of its own), a run that ended in a transport error not counted as an answer; candidate rows by id; `source_check_refusals`, `patch_set`, `merge_set`, `merged_into_existing` and `split` in the job result.
- Context note: each chunk of a longer source gets the headings it starts under, the end of the chunk before and the source's outline, only for understanding (`[ingest] context_note`, `context_note_chars`).
- Review rules: two budgets, `[review] max_repair_rounds` (2) and `max_invalid_retries` (2); every role that asks a model (one table of roles) counts its answers that failed the checks per slot in the job state, so one `sb job advance` asks at most `max_invalid_retries` + 1 times and a job run again does not start over (a host sub-agent's answers that `sb job submit` refuses count the same, and its run is closed once the slot is given up); then a chunk's cards, a split card (its producer or its reviewer) or a disputed card (its judgement again) wait for the owner with the reason, and the merge check, a model note or a diagram is done without; mechanical fixes (`amend`); a focused review in repair rounds; notes of five kinds, and an accept with a `fact`, `unreadable`, `quote` or `not_a_unit` note becomes a revise (each proposition must be right on its own) (`notes_turned`, `review_notes`, shown by `sb job show`).
- Answer checks: every model answer is type-checked against its schema; a wrong shape is refused by name and asked for again, never a crash; ingest answers are parsed as strict JSON.
- Text comparison: one test of "the same text", which sets aside only case, width, spaces and a closed table of marks; a finding only sends an answer back. What the program leaves out by itself is decided in one place: a proposition in the very same words (spaces aside), or a review card whose question and answer both are. A review card that asks the same question with another answer goes back naming both answers (`differs` may keep both). Before a card that takes a patch or a carry is written, the program checks that every item of it is in the card, and stops otherwise.
- Status: `sb status --owner-items` lists everything that waits for the owner; `sb status` reports topics past 25 cards, and `sb curate` gets split proposals for them (extra `curate`).
- `sb export`: writes one map's cards up as an article: outline from the taxonomy, unit after unit by default (`[export] mode`), the writer and reviewer set in `[export.writer]` and `[export.reviewer]`, independent review and smoothing, program checks of citations, numbers and formulas (a MathJax check before any model call, its script installed with the package so an install from git or a wheel has it, a literal `\n` caught), paragraphs that never passed marked in the text and listed; answers that keep failing the checks counted in the job against `max_invalid_retries` (in host mode too), then the unit marked as not reviewed (or, never written, marked where it would stand with why and the cards it was to cover, and listed); Markdown, a report and optional HTML (extra `export`).
- Older jobs: a retry of a partial job of the earlier version is a job of this version and runs to the end; a running job of the earlier version says how to reset it; a job keeps the settings it was frozen with.
- Card diagrams: the model returns a diagram IR that cites the card; code validates it and generates Mermaid, or the card gets no diagram. Batch tools for diagrams already in a vault: audit, prune, re-judge, old-diagram audit, layout gate with the Mermaid build Obsidian ships, write-back.
- Review registry: append-only review log per device, FSRS replay in Python and TypeScript with shared test vectors, `sb review status|queue|log|import-sr`; the daily review page (`sb today`) shows the same queue.
- Obsidian plugin SecondBrain Review: English and Chinese interface that follows the vault's language; today view and dashboard, flip review, Q&A review with LLM grading through AI Providers, card explanations with map context, reminders, one-time import of Spaced Repetition schedules.
- Configuration in TOML, configurable folder layout, keys only from environment variables or commands.
- Vault snapshot cache outside the vault: it compares each card file's bytes with the cached copy and parses only what changed, so a card rewritten with the same size within one timestamp tick is read again; writes always check real file hashes.
- `sb init --catalog <file>` puts a hand-written catalog into a vault, adds the empty card registry and folders, and lists the taxonomy files still to write; until one domain has a topic, `sb ingest` stops before any model call.
- Two example vaults built with the Agent Skill and the tool's own ingest chain: English (42 cards) and Chinese (52 cards).
- README and guides in English and Chinese (`*.zh-CN.md`).
